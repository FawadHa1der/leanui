Verified threads, side by side JavaScript next to iris-lean-proved kernels

Each scenario runs the same work on the same shared resource in several lanes: plain JavaScript (broken on purpose, idiomatic, or the same algorithm by hand) and kernels proved in iris-lean, translated from the very Lean constants the theorems are about into JavaScript over one SharedArrayBuffer. Every lane runs in Web Workers on this page. Each verified lane carries a proof chip that says what is proved, what is trusted, and what is not proved; the chips are built from the generator's manifest. The proofs cover safety under sequentially consistent interleavings: nothing about speed, progress or fairness, and nothing about the JavaScript around a kernel.

Throughput is operations per microsecond, all threads together, measured in this browser on this machine: read it as a ratio between lanes of one run. A page cannot see CPU time; the Node harness (node iris/bench/harness.mjs) reports CPU time per operation and also runs the native and wasm32 lanes. Broken lanes show correctness counts only. Fuzz mode adds random delays before shared-memory operations: more interleavings, not a fair speed comparison. iris/README.md in the repository has the details, the coverage of every JavaScript threading mechanism, and the trusted base.
